# ربات تلگرامی فروش آهن‌آلات

ربات ساده‌ای برای ثبت سفارش، نمایش قیمت‌های روزانه و پیگیری وضعیت سفارش، مخصوص کسب‌وکارهای آهن‌آلات.

## امکانات

**برای کاربر:**
- مشاهده دسته‌بندی‌ها و قیمت‌های به‌روز محصولات
- ثبت سفارش با انتخاب محصول، مقدار، آدرس و شماره تماس
- مشاهده لیست سفارش‌ها و وضعیت هرکدام

**برای ادمین (داخل خود تلگرام، بدون نیاز به پنل جدا):**
- افزودن دسته‌بندی و محصول جدید
- مدیریت کامل محصولات: ویرایش نام، دسته‌بندی، واحد و قیمت؛ فعال/غیرفعال‌کردن و حذف
- ورود و خروج همه محصولات با Excel؛ همراه با گزارش سطرهای نامعتبر
- مشاهده سفارش‌های در انتظار و همه سفارش‌ها
- تغییر وضعیت سفارش (در انتظار / تایید شده / آماده‌سازی / ارسال شده / تحویل داده شده / لغو شده) — با یک لمس، دکمه‌ای

وقتی وضعیت سفارش عوض بشه، ربات خودکار به مشتری پیام می‌ده.

## مراحل راه‌اندازی

### ۱. ساخت ربات در تلگرام
1. به [@BotFather](https://t.me/BotFather) پیام بدید و دستور `/newbot` رو بزنید.
2. یک اسم و یک یوزرنیم (باید به `bot` ختم بشه) انتخاب کنید.
3. توکنی که بهتون می‌ده رو کپی کنید (چیزی شبیه `123456:ABC-DEF...`).

### ۲. گرفتن آیدی عددی تلگرام خودتون (برای ادمین)
به ربات [@userinfobot](https://t.me/userinfobot) پیام بدید تا آیدی عددیتون رو بگیرید.

### ۳. نصب و تنظیم
```bash
# نصب پکیج‌ها
pip install -r requirements.txt

# تنظیم توکن به عنوان متغیر محیطی (پیشنهادی)
export BOT_TOKEN="توکن شما اینجا"
```

فایل `config.py` رو باز کنید و:
- اگه از متغیر محیطی استفاده نکردید، `BOT_TOKEN` رو مستقیم جایگزین کنید.
- آیدی عددی خودتون رو داخل لیست `ADMIN_IDS` قرار بدید:
```python
ADMIN_IDS = [123456789]
```

### ۴. اجرا
```bash
python main.py
```

اگه پیام «ربات در حال اجراست...» رو دیدید، یعنی ربات فعاله. برید توی تلگرام و `/start` رو به ربات بزنید.

### ۵. اضافه کردن اولین محصولات (به عنوان ادمین)
1. به ربات دستور `/admin` رو بزنید تا پنل مدیریت باز بشه.
2. روی «➕ افزودن محصول» بزنید و مراحل رو طی کنید (دسته‌بندی → نام محصول → واحد → قیمت).
3. برای ویرایش، حذف یا فعال/غیرفعال‌کردن محصولات، از «🧰 مدیریت محصولات» استفاده کنید.
4. برای ورود گروهی، فایل Excel با ستون‌های «دسته‌بندی، نام محصول، واحد، قیمت» بفرستید؛ ستون «وضعیت» اختیاری است.

## ساختار پروژه
```
steel_bot/
├── main.py              # نقطه شروع اجرای ربات
├── config.py             # توکن، آیدی ادمین‌ها، تنظیمات
├── database.py            # لایه دیتابیس SQLite
├── keyboards.py            # کیبوردهای شیشه‌ای و معمولی
├── handlers/
│   ├── user.py            # مرور محصولات، ثبت سفارش، وضعیت سفارش
│   └── admin.py            # افزودن/ویرایش/حذف محصول، ورود اکسل، مدیریت سفارش‌ها
├── requirements.txt
└── steel_bot.db           # فایل دیتابیس (خودکار ساخته می‌شه)
```

## دیپلوی روی Render با Docker

این نسخه برای OCR فارسی به Tesseract نیاز دارد؛ بنابراین روی Render باید با Docker اجرا شود. فایل‌های `Dockerfile` و `render.yaml` از قبل آماده‌اند.

1. محتوای پوشه پروژه را در یک ریپازیتوری GitHub قرار دهید.
2. در Render از **New → Blueprint** یا **New → Web Service** استفاده کنید و ریپازیتوری را متصل کنید.
3. در صورت ساخت دستی Web Service، Runtime را روی **Docker** قرار دهید. Build Command و Start Command دستی لازم نیست.
4. Environment Variables زیر را ثبت کنید:
   - `BOT_TOKEN`
   - `ADMIN_IDS`
   - `WEBHOOK_URL`
   - `RECEIPT_ACCOUNT_HOLDER`
   - `RECEIPT_CARD_LAST4`
5. دیپلوی را اجرا کنید. Docker به‌طور خودکار Tesseract، زبان فارسی و وابستگی‌های پایتون را نصب می‌کند.

نمونه مقادیر در فایل `.env.example` قرار دارد.

⚠️ روی پلن رایگان Render ممکن است سرویس پس از مدتی بی‌کاری بخوابد و پاسخ اولین پیام با کمی تأخیر انجام شود. همچنین فایل SQLite روی فایل‌سیستم موقت Render ممکن است با دیپلوی مجدد از بین برود؛ برای داده‌های واقعی از Persistent Disk یا دیتابیس خارجی استفاده کنید.

## اجرای مداوم روی سرور (اختیاری، حالت polling)
برای اینکه ربات همیشه روشن بمونه، می‌تونید از `systemd`، `screen`، `tmux` یا `pm2` (با wrapper) استفاده کنید، یا روی یک VPS با دستور زیر در پس‌زمینه اجراش کنید:
```bash
nohup python main.py &
```

## نکات مهم
- توکن ربات رو هیچ‌وقت جایی عمومی (مثل گیت‌هاب عمومی) قرار ندید — روی Render توی Environment Variables بذاریدش، نه توی کد.
- ⚠️ روی پلن رایگان Render، فایل‌سیستم دائمی نیست؛ یعنی با هر دیپلوی جدید، فایل `steel_bot.db` (و در نتیجه محصولات و سفارش‌هایی که ثبت کردید) پاک می‌شه. برای دائمی موندن داده‌ها یکی از این کارها رو بکنید:
  - از یه **Render Disk** (پرسیستنت استوریج، پولی) استفاده کنید
  - یا دیتابیس رو به یه سرویس خارجی مثل PostgreSQL رایگان (مثلاً Supabase یا Neon) مهاجرت بدید — اگه بخواید کمک می‌کنم این تغییر رو انجام بدیم.
- این نسخه پرداخت آنلاین نداره — سفارش ثبت می‌شه و پرداخت/تسویه به‌صورت جدا (نقدی، کارت‌به‌کارت و...) با مشتری هماهنگ می‌شه. اگه بعداً خواستید درگاه پرداخت (زرین‌پال و...) اضافه کنید، بگید کمکتون می‌کنم.

## بررسی محلی فیش واریزی (بدون API خارجی)

کاربر از منوی «🧾 ارسال فیش واریزی» سفارش را انتخاب و تصویر فیش را می‌فرستد. موتور OCR محلی Tesseract متن فارسی/انگلیسی تصویر را می‌خواند و مبلغ، تاریخ، شماره پیگیری و چهار رقم آخر کارت مقصد را با اطلاعات سفارش مقایسه می‌کند. سپس تصویر و گزارش برای تأیید یا رد نهایی ادمین ارسال می‌شود. تصویر کاملاً تکراری نیز با SHA-256 شناسایی و رد می‌شود.

### متغیرهای محیطی

- `BOT_TOKEN`: توکن جدید بات از BotFather — اجباری
- `WEBHOOK_URL`: آدرس عمومی سرویس Render
- `ADMIN_IDS`: آیدی عددی ادمین‌ها با ویرگول؛ مثل `123456789,987654321` — اجباری
- `RECEIPT_ACCOUNT_HOLDER`: نام صاحب حساب مقصد
- `RECEIPT_CARD_LAST4`: فقط چهار رقم آخر کارت مقصد
- `MAX_RECEIPT_SIZE_MB`: حداکثر حجم تصویر؛ پیش‌فرض `8`
- `OCR_LANG`: زبان‌های OCR؛ پیش‌فرض `fas+eng`
- `OCR_TIMEOUT_SECONDS`: حداکثر زمان هر OCR؛ پیش‌فرض `25`
- `DB_PATH`: مسیر دیتابیس روی Persistent Disk؛ مثل `/var/data/steel_bot.db`

`OPENAI_API_KEY` و هیچ کلید هوش مصنوعی دیگری لازم نیست. پروژه با Docker اجرا می‌شود تا Tesseract و بسته زبان فارسی داخل سرویس نصب شوند.

> OCR فقط اطلاعات قابل مشاهده در تصویر را استخراج می‌کند و نمی‌تواند واریز واقعی یا اصالت قطعی فیش را اثبات کند. تأیید نهایی باید پس از کنترل گردش حساب بانکی توسط ادمین انجام شود.

- پشتیبانی از خالی گذاشتن دسته‌بندی در ردیف‌های متوالی یک گروه
